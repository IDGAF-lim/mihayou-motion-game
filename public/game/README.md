# 游戏与 BLE 原始传感器集成

使用项目根目录的服务，在 Chrome/Edge 通过电脑本机地址打开 `/game/`。推荐手机端为 `apps/MihaSensor-integrated.apk` 0.6.1-ble；手机点启动蓝牙，电脑连接并校准。手机原始数据直接通过 BLE 进入浏览器，Node 提供页面与局号/设置。原始 v0.4.9 APK 的 Wi-Fi 协议保留兼容；选用 BLE 时不混用旧输入。

- `game.js`：组员规则核心、谱面验证、难度窗口、固定偏移、迟到截止、碰撞与通关。
- `app.js`：音频、页面、校准、双人流程和成绩导出。
- `match.js`：从原卡点生成难度配置，双人有效局推进及成绩比较。
- `calibration.js`：节拍匹配、中位数、异常过滤和质量检查。
- `ble-sensor.js`：20 字节协议解码、时钟展开、握姿校准、重力消除、方向示教、冷却恢复与 GATT 生命周期。
- `demo-chart.js`：原 30.004 秒、17 障碍谱面；原 JSON 和 TXT 保留。
- `public/game-link.js`：服务事件、时钟映射和原 App 兼容。

键盘入口：开局/继续自动聚焦游戏画布，↑ 或空格跳跃，↓ 下蹲，无需连接手机；长按只记一次。输入框、下拉选择及可编辑区内保留方向键编辑行为，暂停/结束不发送键盘动作。主工具栏提供对应箭头按钮和悬浮提示。

简单档在原谱面中选取相隔至少 2.3 秒的障碍，窗口 ±220ms；普通原 17 个障碍、±150ms；困难同样 17 个卡点、±100ms、画面较快。没有新增伪卡点。

```text
判定时间 = 映射到音乐轴的动作时间 - 开局偏移
通过条件 = 正确方向且绝对误差不超过本难度窗口
```

BLE 使用手机时间判断 30ms 动作持续确认，使用候选首包的电脑接收时刻映射音乐，不把两个时钟直接相减。550ms 冷却后需要连续 120ms 低活动；不要求反向回正。间断超过 120ms 清除候选并等待静稳；加速度断流 1 秒断开并中断成绩。绝对无线延迟未测量。偏移仅扣一次，准备阶段可调，局内固定。保护期最多 250ms，不扩大动作判定窗口，死亡后不复活。

双人同一手机依次玩。第一位结束后显式换手，第二位重新校准动作再开始。难度和偏移锁定；一组内外部修改配置不改变第二位的比赛参数。有效结束才记成绩；中断重试当前人。通关优先，其次通过障碍数、存活时间；双通关平局。

试听中滑条立即更新补偿后偏差；八拍校准要求至少 6 个稳定样本。页面隐藏、通信断开和切换通信测试局时停止校准，隐藏时游戏暂停。原 APK 断网不能保证立即发现。

`Mihayou.getState()`、`subscribe(fn)`、`start()`、`ready()`、`setCalibration(ms)`、`receiveAction(event)` 保留供调试与旧版接入。BLE 使用自己的连接会话 ID，通过同一游戏动作入口判定。连接选择器在用户点击中打开；重连重新获取全部 GATT 属性，重新校准握姿与方向。

测试方法和真实手机边界参见根目录 README、`验证记录.md`。
