# Android BLE 原始传感器终端

2026-11-17，版本 `0.6.1-ble` / 2，包名 `com.mihayou.sensor.integrated`，名称“咪哈友·蓝牙终端”。基于此前静态恢复工程修改，使用独立开发签名；并非原 APK 的原签名更新。

## 使用

1. 安装 `apps/MihaSensor-integrated.apk`。旧增强版签名不一致时先卸载旧增强版；原版 `com.mihayou.sensor` 可保留。
2. 手机开启蓝牙，点“启动蓝牙”，允许附近设备的广播和连接权限。需要 Android 8+、BLE 外设广播支持和加速度计。
3. 电脑开启蓝牙，用 Chrome/Edge 打开本机游戏页，点“连接手机蓝牙”，选择此手机。无需填 IP，也不要求同一 Wi-Fi。选择器可能显示设备地址。
4. 电脑点“校准动作”，持稳约 1 秒，再按提示上挥一次并停稳至“已就绪”。动作示教不发游戏动作。
5. 开始游戏。换握姿、换人或重连后重新校准。切后台会停止采集、广播及连接，返回后需重新启动。

手机只采集加速度计与游戏旋转向量（缺少时使用普通旋转向量），目标周期 20ms。手机不做握姿校准、重力消除或动作识别。电脑用参考姿态换算并消除静态重力；没有姿态数据时使用时间相关的低通重力估计。

## BLE 协议

Service UUID：`f000aa00-0451-4000-b000-000000000000`

Notify characteristic：`f000aa01-0451-4000-b000-000000000000`，CCCD 标准 UUID `0x2902`。

每个通知固定 20 字节，默认 ATT MTU 也可容纳，无需申请较大 MTU。

| 字节偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | uint8 | 版本 1 |
| 1 | uint8 | 1：原始加速度；2：旋转向量 |
| 2 | uint16 LE | 全流序号，模 65536 |
| 4 | uint32 LE | SensorEvent.timestamp 纳秒转毫秒，模 2^32 |
| 8、12、16 | float32 LE | x、y、z；加速度单位 m/s²，姿态为四元数的向量部分 |

旋转向量标量 w 为负时手机对 xyz 同时取反，电脑按非负 `sqrt(1-x²-y²-z²)` 重建 w，保持相同旋转。毫秒时间约 49.7 天回绕，电脑展开时间与序号并拒绝旧包/重复包。

GATT 服务注册成功后广播，不修改手机的全局蓝牙名称。订阅 CCCD 后才发送；每设备一个在途通知，等待 `onNotificationSent` 再发送下一个。待发数据每种传感器只保留最新一份，优先发送较早样本，超过 150ms 丢弃；不会无限积压。异步失败与权限失败关闭服务。

电脑端的连接、预处理和识别在 `public/game/ble-sensor.js`。连接设置超时 10 秒；有效加速度断流 1 秒则断开并中断成绩。仅收到姿态数据不会延长加速度健康状态。重连重新发现服务和特征并重新校准。相对积压检测不能测出绝对单程无线延迟。

## 识别参数

| 参数 | 初始值 |
| --- | --- |
| 握姿静稳 | 1000ms |
| 示教幅值 | 至少 4m/s² |
| 动作投影阈值 | 3.2m/s²，且至少为模长的 70% |
| 连续动作确认 | 30ms |
| 冷却 | 550ms |
| 释放幅值与静稳 | 模长不超过 1.8m/s²，连续 120ms |
| 最大采样间隔 | 120ms，超过后清候选并重新静稳 |

冷却后静稳即恢复，无需识别反向回正；全程持续采样。参数尚未通过真人实验确定，不能声称零误触或准确率。普通谱面最短间隔 984ms，当前处理时间约 710ms；极限提前/滞后输入与慢速回摆仍可能冲突。

## 构建与测试

使用可运行 `javac --release 8` 的 JDK、Android 35 平台及 Build Tools，运行 `build.ps1`，可传 `-JavaHome -BuildTools -AndroidJar -SigningKey -OutputApk`。本次使用 JDK 11.0.10；通用流程在 `../android/build.ps1`，包含 Windows PowerShell 压缩程序集加载修复。密钥在忽略的 `build/development.jks`，不分发、不入 Git。

APK 已构建并完成 v2/v3 签名验证，未进行实体手机安装或无线传输验收。

`npm test` 覆盖电脑识别、协议与连接生命周期；`npm run test:browser` 模拟浏览器 Web Bluetooth API，送入原始传感器帧，覆盖整曲、断线/断流、重连、双人换手。它们不验证 Android 蓝牙栈和真实无线链路。

`npm run test:sensor` 需要 `JAVA_HOME` 和 `JSON_JAR`，包含 Java `SensorPacket` 20 字节编码与回绕检查，以及保留的旧 `SensorLink`、`SimpleWebSocket`、`PoseFrame`、`SwingDetector` 兼容测试。旧类不再由当前 Activity 使用，旧识别器的 23 条合成断言不是当前 BLE 识别器的测试或真机结果。
